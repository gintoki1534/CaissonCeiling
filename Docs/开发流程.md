# Caisson Ceiling 开发流程

本文档把 `Docs/项目描述content.txt` 拆成可执行开发流程。后续开发尽量都按这里推进，避免 UI、蓝图、交互逻辑、资源接线各自分散。

## 1. 项目总目标

项目目标是做一个 PC 端触摸/鼠标交互的 UE 数字展示作品，围绕隆福寺藻井展开，核心体验分为 3 个板块：

1. `MainMenu`
2. `Level1 / Level1_Introduction`
3. `Level2`
4. `Level3+`
5. `Certificate`

其中当前已经开始的核心开发链路是：

1. `MainMenu` 作为主入口
2. `Level1` 负责介绍与模型浏览
3. `Level1_Introduction` 负责关卡介绍
4. `Level2` 负责“找到并点亮三处核心奇观”
5. `Level3` 及后续尚未开始

## 2. 开发原则

整个项目后续统一遵循下面的开发顺序：

1. 先明确关卡目标，再拆 UI、交互状态、数据结构。
2. 先做“可跑通的最小闭环”，再补动画、音效、演出和美术细节。
3. 每一关都拆成 4 层：
   - 目标定义层：这一关到底什么算完成
   - 交互判定层：用户做了什么操作才算有效
   - 反馈表现层：高亮、提示、UI、音效、镜头
   - 关卡流转层：完成后如何进入下一步
4. C++ 负责稳定的通用底层能力，蓝图负责演出、UI、资源配置和关卡具体接线。
5. 每完成一个阶段，都必须做一次“可交互验证”，而不是只看界面显示。

## 3. 总体开发路线

### 阶段 A：基础框架

目标：把项目的公共能力搭好。

包含内容：

1. 输入系统
2. 相机旋转/观察
3. 点击检测
4. 可交互对象组件
5. UI 打开/关闭
6. 关卡步骤推进
7. 调试日志

完成标准：

1. 玩家可以进入场景
2. 可以旋转观察模型
3. 可以点到模型上的可交互对象
4. UI 能根据步骤变化刷新

### 阶段 B：Level1 介绍与探索

目标：完成“认识藻井”的探索体验。

拆分：

1. 进入介绍对话框
2. 展开详细新手引导
3. 自由观察模型
4. 鼠标悬停高亮可交互部件
5. 点击部件后展示对应介绍
6. 找齐三个部件后解锁下一阶段

完成标准：

1. 三个部件都有唯一 ID
2. 三个部件都能被点击并记录
3. 重复点击不会重复计数
4. 左侧进度 UI 正确更新
5. 三个目标全部完成后才能进入下一阶段

### 阶段 C：Level2 修复阶段

目标：完成修复玩法主循环。

拆分为 4 个子模块：

1. Level2 引导与任务说明
2. 云纹框架修复
3. 星空图修复
4. 阶段结算与过渡

其中云纹框架修复再拆 3 步：

1. 除尘
2. 桐油处理
3. 拼接

星空图修复拆 2 步：

1. 涂抹荞面糊
2. 等待干燥后刷除

完成标准：

1. 每一步都有明确成功条件
2. 每一步都有失败/不足反馈
3. 每一步结束后都能结算文化贡献值
4. 完成一个子步骤后才解锁下一个子步骤

### 阶段 D：证书与收尾

目标：形成完整闭环。

包含内容：

1. 修复完成演出
2. 证书生成
3. 展示修复时间、难度、工具、成果、文化贡献值
4. 重新体验
5. 分享成果

## 4. 关卡开发模板

以后每做一个新关卡，都按这个模板：

### 4.1 需求拆解

输出：

1. 关卡目标
2. 完成条件
3. 失败条件
4. 玩家输入方式
5. UI 需求
6. 数据记录字段

### 4.2 交互设计

输出：

1. 哪些对象可交互
2. 每个对象唯一 ID 是什么
3. 鼠标悬停时的反馈
4. 点击时的反馈
5. 完成时的反馈

### 4.3 程序实现

输出：

1. C++ 通用类或组件
2. 蓝图事件绑定
3. UI 数据绑定
4. 动画/音效触发点

### 4.4 联调验证

必须验证：

1. 正确操作能否通关
2. 错误操作会不会误通关
3. 重复操作会不会重复记分
4. UI 是否和实际状态一致
5. 退出重进后是否可正确重置

## 5. Level2 当前开发顺序

Level2 不要一次做完，按下面顺序推进。

### Step 1：先完成“找到并点亮三处核心奇观”的真实判定

目标：

1. 不能再靠右键直接完成
2. 必须点击 3 个指定目标
3. 每个目标只能记一次
4. 每次成功点击都更新进度 UI
5. 全部完成后才进入下一步

程序侧需求：

1. 每个目标有唯一 `InteractionId`
2. 控制器维护目标列表和已完成列表
3. 点击命中后判断是否属于当前任务
4. 已完成目标进入高亮锁定状态

蓝图侧需求：

1. 给 3 个目标 Actor 挂 `CaissonInteractComponent`
2. 配置 `InteractionId`
3. 绑定点击后的点亮表现
4. 绑定 UI 进度刷新

### Step 2：补齐悬停反馈和镜头演出

目标：

1. 鼠标悬停时对象高亮
2. 有轻提示音
3. 点击后镜头切近景
4. 左侧出现说明信息

### Step 3：接入 Level2 介绍 UI 与任务面板

目标：

1. 进入 Level2 时先播放损毁视频
2. 弹出阶段对话框
3. 关闭后显示详细引导
4. 正式开始任务

### Step 4：进入修复子玩法

顺序固定为：

1. 云纹框架除尘
2. 桐油处理
3. 碎片拼接
4. 星空图清洗

## 6. Level2 当前版本的落地规范

当前阶段先统一采用下面的实现约定：

1. `RequiredLevel2TargetIds` 存本关需要找到的目标 ID
2. 每个目标 Actor 使用 `CaissonInteractComponent`
3. `InteractionId` 必须唯一且稳定，不能依赖显示名判断
4. 通关依赖真实点击命中，不依赖调试快捷键
5. 右键跳过仅保留为调试开关，默认关闭

建议 Level2 的 3 个首批目标 ID：

1. `TiangongTower`
2. `CloudPattern`
3. `StarMap`

## 7. 每次开发前后的固定动作

### 开发前

1. 明确本次只做哪个子目标
2. 确认需要改 C++、蓝图、UI 中的哪几部分
3. 确认完成标准

### 开发后

1. 进场景手动测试
2. 记录哪些蓝图需要继续接线
3. 记录下一步开发入口

## 8. 现在的下一步

当前立刻执行的开发任务只有一个：

1. 完成 `Level2 Step 1`，让玩家必须真正找到并点击 3 个指定目标，才能完成当前流程。

等这一步跑通后，再继续做：

1. 悬停反馈
2. 点亮表现
3. 镜头切换
4. 说明 UI
5. 修复子玩法
