# Caisson Ceiling 开发流程

本文档把 `Docs/项目描述content.txt` 拆成可执行开发流程。后续开发尽量都按这里推进，避免 UI、蓝图、交互逻辑、资源接线各自分散。

配套文档：

  - 说明当前重构成果、职责边界与开发原则
- `Blueprint_Architecture.md`
  - 说明当前蓝图资产结构和已确认接线
- `README.md`
  - 文档总索引，方便开发者和 AI 快速定位当前蓝图状态、导出文档和维护入口

## 1. 项目总目标

项目目标是做一个 PC 端触摸/鼠标交互的 UE 数字展示作品，围绕隆福寺藻井展开，核心体验分为 3 个板块：

1. `MainMenu`
2. `Level1 / Level1_Introduction`
3. `Level2`
4. `Level3+`
5. `Certificate`

其中当前已经开始的核心开发链路是：

1. `MainMenu` 作为主入口
2. `Level1` 负责介绍与模型浏览
3. `Level1_Introduction` 负责关卡介绍
4. `Level2` 负责“找到并点亮三处核心奇观”
5. `Level3` 及后续尚未开始

## 2. 开发原则

整个项目后续统一遵循下面的开发顺序：

1. 先明确关卡目标，再拆 UI、交互状态、数据结构。
2. 先做“可跑通的最小闭环”，再补动画、音效、演出和美术细节。
3. 每一关都拆成 4 层：
   - 目标定义层：这一关到底什么算完成
   - 交互判定层：用户做了什么操作才算有效
   - 反馈表现层：高亮、提示、UI、音效、镜头
   - 关卡流转层：完成后如何进入下一步
4. C++ 负责稳定的通用底层能力，蓝图负责演出、UI、资源配置和关卡具体接线。
5. 每完成一个阶段，都必须做一次“可交互验证”，而不是只看界面显示。

补充约定：

1. 如果涉及输入、步骤状态、点击判定、页面生命周期，先改 C++，再接蓝图。
2. 如果只是动画、图标、文案、显隐、材质和镜头演出，优先在蓝图里完成。
3. 蓝图实际接线修改后，记得同步更新 `Blueprint_Architecture.md`。

## 3. 总体开发路线

### 阶段 A：基础框架

目标：把项目的公共能力搭好。

包含内容：

1. 输入系统
2. 相机旋转/观察
3. 点击检测
4. 可交互对象组件
5. UI 打开/关闭
6. 关卡步骤推进
7. 调试日志

完成标准：

1. 玩家可以进入场景
2. 可以旋转观察模型
3. 可以点到模型上的可交互对象
4. UI 能根据步骤变化刷新

### 阶段 B：Level1 介绍与探索

目标：完成“认识藻井”的探索体验。

拆分：

1. 进入介绍对话框
2. 展开详细新手引导
3. 自由观察模型
4. 鼠标悬停高亮可交互部件
5. 点击部件后展示对应介绍
6. 找齐三个部件后解锁下一阶段

完成标准：

1. 三个部件都有唯一 ID
2. 三个部件都能被点击并记录
3. 重复点击不会重复计数
4. 左侧进度 UI 正确更新
5. 三个目标全部完成后才能进入下一阶段

### 阶段 C：Level2 修复阶段

目标：完成修复玩法主循环。

拆分为 4 个子模块：

1. Level2 引导与任务说明
2. 云纹框架修复
3. 星空图修复
4. 阶段结算与过渡

其中云纹框架修复再拆 3 步：

1. 除尘
2. 桐油处理
3. 拼接

星空图修复拆 2 步：

1. 涂抹荞面糊
2. 等待干燥后刷除

完成标准：

1. 每一步都有明确成功条件
2. 每一步都有失败/不足反馈
3. 每一步结束后都能结算文化贡献值
4. 完成一个子步骤后才解锁下一个子步骤

### 阶段 D：证书与收尾

目标：形成完整闭环。

包含内容：

1. 修复完成演出
2. 证书生成
3. 展示修复时间、难度、工具、成果、文化贡献值
4. 重新体验
5. 分享成果

## 4. 关卡开发模板

以后每做一个新关卡，都按这个模板：

### 4.1 需求拆解

输出：

1. 关卡目标
2. 完成条件
3. 失败条件
4. 玩家输入方式
5. UI 需求
6. 数据记录字段

### 4.2 交互设计

输出：

1. 哪些对象可交互
2. 每个对象唯一 ID 是什么
3. 鼠标悬停时的反馈
4. 点击时的反馈
5. 完成时的反馈

### 4.3 程序实现

输出：

1. C++ 通用类或组件
2. 蓝图事件绑定
3. UI 数据绑定
4. 动画/音效触发点

### 4.4 联调验证

必须验证：

1. 正确操作能否通关
2. 错误操作会不会误通关
3. 重复操作会不会重复记分
4. UI 是否和实际状态一致
5. 退出重进后是否可正确重置

## 5. Level2 当前开发顺序

Level2 不要一次做完，按下面顺序推进。

### Step 1：先完成“找到并点亮三处核心奇观”的真实判定

目标：

1. 不能再靠右键直接完成
2. 必须点击 3 个指定目标
3. 每个目标只能记一次
4. 每次成功点击都更新进度 UI
5. 全部完成后才进入下一步

程序侧需求：

1. 每个目标有唯一 `InteractionId`
2. 控制器维护目标列表和已完成列表
3. 点击命中后判断是否属于当前任务
4. 已完成目标进入高亮锁定状态

蓝图侧需求：

1. 给 3 个目标 Actor 挂 `CaissonInteractComponent`
2. 配置 `InteractionId`
3. 绑定点击后的点亮表现
4. 绑定 UI 进度刷新

### Step 2：补齐悬停反馈和镜头演出

目标：

1. 鼠标悬停时对象高亮
2. 有轻提示音
3. 点击后镜头切近景
4. 左侧出现说明信息

### Step 3：接入 Level2 介绍 UI 与任务面板

目标：

1. 进入 Level2 时先播放损毁视频
2. 弹出阶段对话框
3. 关闭后显示详细引导
4. 正式开始任务

### Step 4：进入修复子玩法

顺序固定为：

1. 云纹框架除尘
2. 桐油处理
3. 碎片拼接
4. 星空图清洗

## 6. Level2 当前版本的落地规范

当前阶段先统一采用下面的实现约定：

1. `RequiredLevel2TargetIds` 存本关需要找到的目标 ID
2. 每个目标 Actor 使用 `CaissonInteractComponent`
3. `InteractionId` 必须唯一且稳定，不能依赖显示名判断
4. 通关依赖真实点击命中，不依赖调试快捷键
5. 右键跳过仅保留为调试开关，默认关闭

建议 Level2 的 3 个首批目标 ID：

1. `TiangongTower`
2. `CloudPattern`
3. `StarMap`

## 7. 每次开发前后的固定动作

### 开发前

1. 明确本次只做哪个子目标
2. 确认需要改 C++、蓝图、UI 中的哪几部分
3. 确认完成标准

### 开发后

1. 进场景手动测试
2. 记录哪些蓝图需要继续接线
3. 记录下一步开发入口

## 8. 现在的下一步

当前 `Level2 Step 1` 已经跑通，而且“正确点击目标 -> 镜头拉近 -> 显示介绍 UI -> 点击介绍 UI -> 回原视角”的闭环也已接通。下一步不再是“把三处目标点出来”，而是把这一阶段真正收尾并接上后续体验。

当前立刻执行的开发任务建议按下面顺序推进：

1. 云纹框架修复

## 9. 当前开发进度（基于本轮开发对话整理）

本节只记录当前已经明确完成、已验证或已约定的内容，作为后续继续开发 `Level2` 和后续关卡的接续依据。

### 9.1 已完成的公共基础工作

1. 项目文本编码已统一约定为 `UTF-8`。
2. `Level1 / Level2` 的模型展示链路已从“UI 中的 RenderTarget 模型显示”调整为“真实世界模型显示”。
3. 藻井展示 Pawn 的基础结构已理顺，模型旋转与相机结构已拆开，当前可以稳定拖拽观察藻井。
4. 背景图已改为世界中的背景板方案，不再用 `W_Level1` 中央背景图直接覆盖模型区域。
5. `Level1` 中会挡住模型交互的中央背景图问题已定位并规避，模型区域已不再被该 UI 背景直接拦截。

### 9.2 Level2 Step 1 当前已完成内容

`Level2 Step 1` 的目标是：玩家必须真实找到并点击 3 个目标，完成“找到并点亮三处核心奇观”。

当前已经完成：

1. `Level2` 不再依赖右键直接完成流程，右键只保留为可关闭的调试能力。
2. 已建立 3 个真实可点击目标：
   - `TiangongTower`
   - `CloudPattern`
   - `StarMap`
3. 目标模型已拆分并整理为独立可交互对象，当前交互是基于真实世界模型，而不是 UI 贴图。
4. 鼠标悬停到对应目标时，C++ 已能正确输出进入/离开对象的调试日志。
5. 左键点击输入链路已补齐，点击目标时已经可以推进 `Level2` 当前步骤。
6. 当前点击推进已经验证通过，说明：
   - 射线命中链路有效
   - 目标 `InteractionId` 配置已接通
   - `Level2` 步骤推进逻辑已接通
7. 当前 `Level2 Step 1` 已改为严格顺序点击：
   - 先 `TiangongTower`
   - 再 `CloudPattern`
   - 最后 `StarMap`
8. 当前已修正“点错也点亮”的问题，只有顺序正确时才会触发正式点亮与步骤推进。
9. 当前已实现“点击后正式点亮”的基础表现，并且整体效果已接近最终需求。
10. 当前已接入“点击正确目标 -> 镜头拉近到对应位置 -> 展示介绍 UI -> 点击介绍 UI -> 回原视角”的流程闭环。
11. 当前介绍 UI 采用 3 个独立介绍面板与对应按钮，按钮点击后会触发视角回原位。

### 9.3 Level2 当前视觉与交互表现现状

当前已经确认的效果：

1. 藻井可正常显示在世界中。
2. 拖拽鼠标时，藻井可围绕自身中心旋转。
3. `Level2` 点击目标后可按正确顺序推进步骤。
4. 当前已经做出目标点亮效果，并经过多轮调试后，效果已接近可用状态。
5. `Level2` UI 中原本可编辑的文本框问题已修正，相关文本现已改为不可编辑的展示用途。
6. 当前高亮/点亮表现不建议依赖统一替换全部材质，而应继续沿用适配多材质目标的表现方案。
7. 当前正确点击目标后，镜头可自动拉近到对应观察点。
8. 当前 `W_Level2` 已能根据目标显示对应介绍面板，按钮点击后会触发 `BP_ShowcaseModel` 回原视角。
9. 当前回原视角完成后，`W_Level2` 会通过 Controller 回调继续放开下一次目标点击。

当前仍需继续完善或继续打磨的表现：

1. 悬停高亮需要继续按最终美术效果收尾。
2. 点击后的“正式点亮”效果虽然已基本可用，但仍可继续优化细节与统一风格。
3. 当前发光实现已经不建议走“统一替换所有材质”的路线，应继续保持“适配多材质目标”的实现思路。
4. 第三次介绍结束后的右下角“点击任何地方继续”提示还需要最终联调确认。
5. `Level2 -> Level3` 的最终跳转接线和完整验收还需要继续完成。

### 9.4 当前已经验证过、不再建议回退的实现结论

以下结论已经在本轮开发中通过问题排查得到，后续开发建议直接遵守：

1. 不要再回到 `W_Level1 / W_Level2` 中通过 `RT_ModelViewer` 直接显示藻井模型的方案，否则容易重新引入重复模型、幽灵模型和点击错位问题。
2. `Level1 / Level2` 的核心交互对象应继续使用真实世界中的藻井模型。
3. 中央模型区域不应再被全屏背景图或可命中的 UI 覆盖。
4. 目标模型的高亮与点亮效果，不建议依赖“统一替换全部原材质”，因为当前目标模型包含多种材质、多个材质槽和多个部件。
5. 后续应继续坚持“C++ 负责稳定交互状态，蓝图负责视觉演出与资源接线”的分工。
